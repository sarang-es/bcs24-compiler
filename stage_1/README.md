# Bcs24 Compiler — Stage 1: Lexical Analyzer & Parser

## What We Did

In Stage 1, we built a **Lexical Analyzer** (scanner) and a **Parser** (syntax checker) for the **Bcs24** programming language. The goal is: given a Bcs24 source file, determine whether it is syntactically valid or not.

- If the program is valid → prints **`Parsing Successful`**
- If the program has a syntax error → prints **`Syntax Error`**

We used two automatic program generators:
- **Flex** — generates the lexer (scanner) from `lexer.l`
- **Bison** — generates the parser from `parser.y`

---

## Project Files

### Source Files (written by us)

| File | Purpose |
| :--- | :--- |
| `lexer.l` | **Flex specification** — defines token patterns (keywords, operators, identifiers, numbers, whitespace) using regular expressions. Flex reads this and generates `lex.yy.c`. |
| `parser.y` | **Bison specification** — defines the Bcs24 grammar rules (program structure, declarations, statements, expressions). Bison reads this and generates `parser.tab.c` and `parser.tab.h`. |
| `main.c` | **Driver program** — contains the `main()` function (opens the input file, calls the parser) and `yyerror()` (prints "Syntax Error" when the parser detects an invalid program). |

### Generated Files (created by Flex and Bison)

| File | Generated by | Purpose |
| :--- | :--- | :--- |
| `lex.yy.c` | `flex lexer.l` | C source code for the lexer. Contains the `yylex()` function and DFA tables that convert raw text into tokens. |
| `parser.tab.c` | `bison -d parser.y` | C source code for the parser. Contains the `yyparse()` function and LALR(1) parsing tables that check grammar rules. |
| `parser.tab.h` | `bison -d parser.y` | C header file with token number definitions (e.g., `#define BCSMAIN 258`, `#define PLUS 265`). This file is included by `lexer.l` so the lexer and parser agree on token numbers. |

## How It Works

The compiler pipeline for Stage 1:

```
  Input File (.bcs)
       │
       ▼
  ┌──────────┐     Reads characters, matches regex patterns,
  │  LEXER   │     returns token numbers (e.g., BCSMAIN=258, PLUS=265)
  │ (yylex)  │     Generated from: lexer.l → lex.yy.c
  └──────────┘
       │ tokens
       ▼
  ┌──────────┐     Receives tokens from lexer, checks if the sequence
  │  PARSER  │     of tokens matches the Bcs24 grammar rules
  │ (yyparse)│     Generated from: parser.y → parser.tab.c
  └──────────┘
       │
       ▼
  "Parsing Successful" or "Syntax Error"
```

### Step-by-step flow:

1. `main()` in `main.c` opens the input `.bcs` file and sets `yyin` (the lexer's input stream).
2. `main()` calls `yyparse()` — the parser function in `parser.tab.c`.
3. `yyparse()` repeatedly calls `yylex()` — the lexer function in `lex.yy.c` — to get the next token.
4. `yylex()` reads characters from the input file, matches them against the regex rules in `lexer.l`, and returns the corresponding token number.
5. `yyparse()` uses the LALR(1) parsing table to check if the sequence of tokens matches the grammar.
6. If parsing succeeds (return value 0), `main()` prints `"Parsing Successful"`.
7. If a syntax error is detected, `yyparse()` calls `yyerror()`, which prints `"Syntax Error"`.

## How to Compile

### Prerequisites
- `gcc` (C compiler)
- `flex` (lexical analyzer generator)
- `bison` (parser generator)

### Using Makefile (recommended)
```bash
make
```
This single command runs all three steps below automatically.

### Manual Compilation (step by step)

**Step 1: Generate parser C code from grammar specification**
```bash
bison -d parser.y
```
- Input: `parser.y`
- Output: `parser.tab.c` (parser source) and `parser.tab.h` (token definitions header)
- The `-d` flag tells Bison to generate the `.h` header file

**Step 2: Generate lexer C code from token specification**
```bash
flex lexer.l
```
- Input: `lexer.l`
- Output: `lex.yy.c` (lexer source)
- Must run after `bison` because `lexer.l` includes `parser.tab.h`

**Step 3: Compile all C files into the executable**
```bash
gcc -Wall -Wextra -o bcs24_parser parser.tab.c lex.yy.c main.c
```
- Input: `parser.tab.c`, `lex.yy.c`, `main.c`
- Output: `bcs24_parser` (the executable)
- `-Wall -Wextra` enables all warnings for clean code

**Order matters:**
1. `bison` must run first (creates `parser.tab.h` needed by `lexer.l`)
2. `flex` must run second (needs `parser.tab.h` to exist)
3. `gcc` must run last (compiles all generated `.c` files)

## Bcs24 Language Grammar

The grammar defines the structure of a valid Bcs24 program:

```
program   → BcsMain { declist stmtlist }

declist   → declist decl | decl
decl      → type id ;
type      → int | bool

stmtlist  → stmtlist ; stmt | stmt          (semicolon is a SEPARATOR, not terminator)
stmt      → id = aexpr
          | if (expr) {stmtlist} else {stmtlist}
          | while (expr) {stmtlist}

expr      → aexpr relop aexpr | aexpr
relop     → < | > | <= | >= | == | !=

aexpr     → aexpr + aexpr | term
term      → term * factor | factor
factor    → id | num
```

### Key Points:
- Every program starts with `BcsMain { ... }`
- Declarations come first, then statements
- Semicolons are **separators** between statements (not terminators — no trailing semicolon after the last statement)
- `if` statements **must** have an `else` clause
- Only `+` and `*` operators are supported for arithmetic (no `-` or `/`)

---

## Tokens Recognized by the Lexer

| Token Type | Patterns |
| :--- | :--- |
| Keywords | `int`, `bool`, `if`, `else`, `while`, `BcsMain` |
| Identifiers | `[a-zA-Z][a-zA-Z0-9]*` (starts with letter, followed by letters/digits) |
| Numbers | `[0-9]+` (one or more digits) |
| Relational Operators | `<`, `>`, `<=`, `>=`, `==`, `!=` |
| Arithmetic Operators | `+`, `*` |
| Assignment | `=` |
| Delimiters | `;`, `(`, `)`, `{`, `}` |
| Whitespace | spaces, tabs, newlines (ignored) |
